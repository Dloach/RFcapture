## 0. 一句话结论

**已定案（2026-11-08 15:10）：回放时帧间不该有任何空隙。**

干净波形的帧结构解析（`signals-2026-11-08.log`）证明：原遥控按住时**帧与帧背靠背**——同步头精确地每 50 个脉冲出现一次（#1 `rollUP`：50/50/50；#3 `rollDOWN`：50/50），中间**没有** 12.5ms 空隙。此前"空隙 12.5ms"是从脏波形（`12528/12720`，毛刺合并产物）里误读出来的。

- 老记录（≥2 帧背靠背）回放能开闸 → 每次重复都送出**连续多帧**；
- 新记录（单帧 50 脉冲）回放不能开闸 → `send()` 默认 `gapUs=12500`，每帧后插 12.5ms 死区，重复 3 次或 9 次都只是**孤立帧**，接收端凑不出它需要的连续相同帧。

修复：`OokTransmitter::send()` 默认 `gapUs=0`（背靠背回放），发送侧按"一次真实按键长度"（约 300 脉冲）自动补足重复次数。

**已实测确认（2026-11-08 16:00 前后）**：修复固件下重新采样，得到新的单帧记录（n=50），从采集页直接按 `S`
发送，铁闸正常动作，可反复操控。此时发送侧发出 6 个连续帧（50 × 6 = 300 脉冲），与老记录（160 脉冲内含
3 个连续帧）的效果一致——反过来也印证了结论：接收端要的是**连续**帧，不是总帧数。

## 0.1 历史结论（已被上面推翻，保留供参考）

同一台设备、同一个发射通道：

- **老记录**（多帧拼接的 160 脉冲波形，采集于早期 RMT 版本固件）→ 回放**能**开闸；
- **新记录**（从同步头开始、干净的单帧 50 脉冲）→ 回放**不能**开闸；
- 把新记录的重复次数从 3 次加到 9 次，依然不能；
- 但新记录里**未裁剪**的那条（121 脉冲，含帧间空隙）曾经能开闸一次。

所以问题不在"解码"，而在 **存下来的波形尾部和帧间空隙**：把帧裁成正好 50 个脉冲（丢掉帧尾那段长低电平）后，接收端就不认了。

## 3. 实验时间线（改动 → 实测）

### 3.1 早期（固件能正常采集/回放铁门）

| 改动 | 结果 |
| --- | --- |
| RMT 接收 + RadioLib 寄存器 + PATABLE +10 dBm | 315 铁门：采集、保存、回放成功（门开） |
| 回放 6 份 × 160 脉冲 | 门开，但继电器"像机枪一样"响 → 改为更少次数 |

### 3.2 换中断接收（本次会话）

| 改动 | 结果 |
| --- | --- |
| 原因：433 下 RMT 缓冲持续溢出（`RX buffer too small` 每秒数十条），因为解调器在 433 输出连续噪声 | — |
| 换成 GPIO 中断 + micros() 时间戳 + 软件环形缓冲 | 不再刷屏；但一开始毛刺会把高低交替打断 → 修复（毛刺后的续接脉冲并回同一脉冲） |
| 每次切频段改为 SRES + 完整重配（原来只写 FREQ+SCAL） | 433 不再持续抖动 |

### 3.3 解码与存储的改动（这是"新采集失败"的分界点）

| 改动 | 结果 |
| --- | --- |
| 解码只认 24 位（此前 20/21 位噪声会被误判成 EV1527，出现"碰巧采到别人的信号"） | 误判消失 |
| 解析**只取同步头后的前 24 位**（此前会一直解析到 32 对，取末尾 24 位 → 码值随样本漂移） | 码值稳定：`345671/345674/345678` 低几位恰好不同，符合按键位 |
| 存储改为**从同步头开始** | `#3 23456F` 就是从同步头开始、121 脉冲 → 用户确认"新的下降能用了" |
| 再把存储**裁剪成正好 50 脉冲**（同步头 + 24 位，丢掉帧尾长低电平） | 新采集三条全部发送失败（3 次、9 次都不行）← **当前问题** |
| 已回退该裁剪（保留同步头起点 + 保留帧尾空隙） | 复测仍失败 → 帧尾空隙不是症结，见 §3.4 / §7 |

### 3.4 发送侧的改动

| 改动 | 结果 |
| --- | --- |
| 固定 3 份 | 老记录 OK |
| 按帧数自动补足到约 480 脉冲（新 50 脉冲帧 → 9 份） | 新记录仍失败 |
| 曾尝试用"码值 + T 重建单帧"发送 | 铁门/铁闸都不认 → 已放弃，改回原始波形回放 |
| 回放帧间空隙 9 ms → **12.5 ms**（与老波形实测的 12528/12720 对齐），同时不再裁剪帧尾 | 复测仍失败 → 12.5 ms 本身就是从脏波形误读的，见 §7 |

## 4. 已确认的事实

1. **发射通道正常**：同一固件、同一位置，老记录（160 脉冲）能开闸。
2. **接收通道正常**：同一固件能采到新波形，1T/3T/31T 比例正确。
3. **解码结果自洽**：三条新码低字节不同（`0x71/0x74/0x78`），与"开/停/降"三个键对应。
4. **失败与"波形被裁成 50 脉冲"强相关**：未裁剪的 121 脉冲版本曾经成功。
5. 帧间空隙实测约 **12.5 ms**（老波形里可见 12528、12720），我们的回放空隙是 **9 ms**。

## 5. 主要假设（供分析）

| # | 假设 | 支持证据 | 反证/待验 |
| --- | --- | --- | --- |
| A | 接收端要求帧尾低电平足够长（≈12.5 ms），裁成 50 脉冲后帧尾只剩 1T/3T + 我们加的 9 ms，被接收端判为**长低电平同步**导致下一帧失步 | 未裁剪的 121 脉冲版本能用；裁剪后全失败 | 尚未把空隙改成 12.5 ms 复测 |
| B | 需要 ≥4~5 个连续相同帧才能被接收 | 老记录一次发 9 帧能开 | 新记录发 9 帧仍失败，B 不足以解释 |
| C | 新采集的码值虽自洽，但**位对齐差一位**（因为我们的 bit0 是最后发的），导致发出去的波形与遥控原波形不同 | — | 但我们发的是**原始波形**而非重建帧，与码值无关 → C 不影响发射 |
| D | 遥控在"下降/停止"上可能带**重复帧或长按**语义 | 老波形里同一条含多帧 | 未验证 |

**最可疑的是 A**：把帧尾裁剪掉等于改变了帧与帧之间的间隔结构。

> **本节写于定案之前，结论已被 §7 取代，仅供追溯**：A **错误**（帧尾空隙是脏波形误读）；B 方向对但关键在
> 「**连续**」——9 个被死区隔开的孤立帧 ≠ 9 个连续帧；C、D 与问题无关（回放的是原始波形）。

## 6. 建议的下一步（按性价比排序）

1. **把回放帧间空隙从 9 ms 改成 12.5 ms**（`OokTransmitter::send(..., gapUs)`）——**已改并烧录**，待用新记录复测。
2. **不要裁剪 50 脉冲**，改成"同步头起点 + 至少含 2 个完整帧 + 原始帧间空隙"（即保留 121~160 脉冲）。
3. 用同一固件采一条**老记录对应的按钮**（例如"停止"），比较新老两条波形的帧尾长度：
   - 若老记录帧尾低电平 ≈12.5 ms、新记录 ≈0.3 ms，则假设 A 成立。
4. 若仍失败，可试"发 2 帧后停 100 ms 再发 2 帧"（模拟连按两次）。
5. 让另一个 AI 重点看：**EV1527 接收端对帧尾低电平/帧间隔的容忍范围**，以及"整帧 50 脉冲 + 9 ms 空隙"与"帧尾并入 12.5 ms 空隙"在解码器看来是否等价。

## 7. 定案分析（15:10）

对 `signals-2026-11-08.log` 全部记录做帧结构解析（找 >15T 的低电平 = 同步头）：

| 记录 | 帧结构 | 回放结果 |
| --- | --- | --- |
| saved #1 rollUP n=160 | 3 个完整帧背靠背 + 第 4 帧前 10 脉冲 | 能开闸 |
| saved #3 rollDOWN n=121 | 2 个完整帧背靠背 + 21 脉冲尾巴 | 能开闸（"下降"） |
| capd #0..#2 n=50 | 恰好 1 个完整帧 | 3 次、9 次都失败 |

帧间距全部为 0（下一帧的同步高电平紧跟上一帧末位的低电平）。对照 §5 的假设：

- 假设 A（需要 12.5ms 帧尾空隙）**错误**——那是脏波形的毛刺合并值；
- 假设 B（需要多帧）方向对但关键是**连续**：9 个被 12.5ms 死区隔开的孤立帧 ≠ 9 个连续帧；
- 假设 C、D 不相关（回放的是原始波形）。

修复改动：

1. `src/ook_tx.h`：`send()` / `sendCode()` 默认 `gapUs` 从 12500/10000 改为 **0**；
2. `src/app.cpp` `sendCapture()` / `sendSaved()`：显式 `gapUs=0`，重复次数目标从 480 脉冲改为 300 脉冲（≈一次按键的长度）；`[tx]` 日志改为打印实际 `reps`（原来固定打 `txRepeats`，有误导）。
