## 0. 三个功能现在各自什么状态

设备上当前烧录的固件：**"只在进 BACKUP 时给模块复位脉冲"** 那一版。

| 功能 | 状态 | 说明 |
|---|---|---|
| 分层菜单（RF TOOLS / NFC TOOLS / BACKUP） | ✅ 可用 | 冷启动一定回到选择页；软件重启保留当前功能 |
| RF TOOLS（采集 / 发送 / 扫频） | ✅ 可用 | 未受本轮改动影响 |
| NFC 读卡 | ⚠️ 取决于上一次是否用过 BACKUP | 见下面的总线冲突 |
| NFC 模拟（开门） | ✅ **已验证能开门** | 走 `CARD LIST` → 选 `3C02B611` → ENTER |
| BACKUP（RF 信号 + NFC 卡片写 TF 卡） | ⚠️ 取决于上一次是否用过 NFC | 见下面的总线冲突 |

**核心未解问题：NFC 和 TF 卡不能在同一次上电里都用。**
用 NFC 之后，TF 卡会挂不上（`cardType=0`，601 ms 超时），只有**彻底断电**才能恢复；
反过来，进 BACKUP 前若打了复位脉冲，TF 卡能用，但那次上电里 NFC 芯片起不来。

## 1. 硬件上的真实冲突

CAP.CC1101 模块上两颗芯片 + 主板 TF 卡槽共用 **SCK=40 / MOSI=14 / MISO=39**：

| 设备 | CS | SPI 模式 | 供电 |
|---|---|---|---|
| CC1101 | 5 | 0 | 模块 DCDC，由 **G3(POWER_EN)** 使能 |
| ST25R3916 (NFC) | 6 | **1**，10 MHz | 同上（同一颗 DCDC） |
| TF 卡 | 12 | 0 | 主板自身 3V3 |

M5 的 NFC 库 `wiring::addSPI(units, unit, 10000000, 1)` 明确用 **mode 1**。

## 2. 本轮做过的实验（全部上机）

| # | 改动 | NFC | TF 卡 | 结论 |
|---|---|---|---|---|
| 1 | 基线（无任何处理） | ✅ | ❌ 用过 NFC 后必坏，断电恢复 | 卡被锁死 |
| 2 | 上电把 **CS12 拉高** | ✅ | ❌ 无改善 | CS 悬空不是主因 |
| 3 | SD 挂载前 **G3 拉低断电**（长期） | ❌ 芯片无电 | ❌ 更糟 | 断电反而让未上电的芯片钳住 MISO |
| 4 | 上电给模块 **60ms 复位脉冲**（低→高） | ❌ `addSPI+begin=0` | ✅ **能用** | 脉冲治好了 SD，弄死了 NFC |
| 5 | 脉冲后等 500 ms + NFC 初始化重试 ×4 | ❌ 仍然失败 | ✅ | 不是时间不够 |
| 6 | 用 **SPI 总线恢复**（各 CS 高 + 16 个时钟）代替脉冲 | ✅ | ❌ **又把 SD 弄坏** | 打时钟会破坏卡的状态 |
| 7 | 回滚到基线 | ✅ | ❌ | 回到起点 |
| 8 | **只在 BACKUP 启动时打脉冲** | 取决于上次 | 取决于上次 | 当前烧录版；两者仍需"不同上电" |

**没有一次实验同时满足两者。** 这说明根因不是某一个引脚状态，而是"ST25R3916 被使用后，
在复位前会一直占着 MISO"这件事——而给模块复位又会破坏它自己的启动。

## 4. 明天建议的验证顺序

1. **先固定一个已知可用版本**：把 `git` 提交打在当前状态上（见 §5），任何实验都可回退。
2. 用**两块上电**的笨办法先让功能可用：
   - 要 NFC（读卡/模拟）→ 冷启动 → `NFC TOOLS`
   - 要备份 → 冷启动 → `BACKUP`
   并把这条写进用户文档，不再让人试。
3. 再攻根因，优先级从高到低：
   a. **查 ESP-IDF 官方 `sdspi_share` 文档**（沙箱里 web_fetch 被挡，需要换网络或用手机看）：
      https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/sdspi_share.html
      重点看它对"共享总线上其他设备"的要求，特别是 **`spi_bus_initialize` 后如何让别的设备临时让出总线**。
   b. 读 `M5Unit-NFC` 里 `unit_ST25R3916` 的 SPI 事务实现，确认**每次事务后是否 `endTransaction()`、
      CS 是否回到高**；若发现某条路径漏了，那就是根因（也解释了为什么只有 NFC 会锁卡）。
   c. 试 **在离开 NFC 功能时（esc 回菜单前）主动 `units.end()` / 把 CS6 拉高**，看 TF 是否恢复。
      这一步比上面打脉冲安全得多，值得先试。
   d. 若都不行：硬件上给 SD 加一个掉电恢复（拔卡重插即可恢复？）——先验证"重新插拔卡"是否
      等价于断电，若是，用户可自愈，代价可接受。

## 6. 已验证可用的关键结论（别丢）

1. **NFC 模拟能开门**，配方见 `docs/DEV-STATE.md` §14.2：Ultralight 载具 + 真实 UID +
   采集到的 ATQA/SAK（`0004`/`08`）+ `units.update()` 每轮 + 会话中不打印。
2. 门卡是 **`3C02B611`**（列表里第二张），第一张 `2BF6276F` 不是门卡。
3. 键盘芯片 TCA8418 会被高频 I2C 打死（每帧读电量），MCU 复位清不掉，只能断电。
4. 天线场必须**只在轮询瞬间打开**，否则键盘会死。

## 7. 后续修复（2026-11-12 晚间，全部上机验证）

### 7.1 NFC × TF 共存：根因翻案 + 已修

§0/§2 里"ST25R3916 占着 MISO"的假设**是错的**。实机日志抓到决定性证据：
没碰 NFC 时 SD 挂载 24ms 成功（type=3），进过 NFC TOOLS 后四个频率全部 601ms 超时。
根因是 **13.56MHz 载波**：库的 `configure_nfc_a()` 在 `begin()` 结束时把场打开
（`nfc_initial_field_on`），而 ST25R3916 独立供电、寄存器跨 ESP32 重启不丢——
哪怕只是进了 NFC TOOLS 没扫描，载波也一直辐射，下一个功能的 SD 初始化被干扰。
G3 脉冲当年"治好"SD 只是顺便断了载波，代价是 SPI 引脚反灌让芯片半供电锁死（§2 实验 4/5）。

修法（替代脉冲，已验证同一次上电里 NFC 和 TF 都能用）：

1. **`sd_mount.h`**：挂卡前对 ST25R3916 发 `CMD_SET_DEFAULT`（裸 SPI 两个字节，
   载波关闭、寄存器归位；NFC 下次启动反正从头配置，无副作用）。
2. **`main.cpp`**：删 G3 脉冲，改为任何启动路径先把 CS5/CS6/CS12 拉高、G3 保持供电。
3. **`nfc_app.cpp`**：读卡模式 `begin()` 后立即灭场；扫描改为**每轮 detect 前开、后关**
   （之前的实现只关不开，第一轮之后天线永远静默——"读不到任何信号"的真因）；
   退出 NFC 功能的每条路径都灭场。

### 7.3 新功能：首页快捷九宫格

首页改为左菜单 + 右 3×3 网格（`8 9 0 / I O P / J K L`）：

- **绑定**：RF 的 SEND 页 / NFC 的 CARD LIST 选中条目按 `B` → 选格子 → 选图标 → 选颜色
  （选择器里 `D` 删绑定）；图标 8 个（方向三角/方块/圆/门/闪电），颜色 8 色
- **RF 一键发送**：**不重启**，首页初始化 CC1101（仅 TX）直接发 ~700ms，可连续点动
- **NFC 一键模拟**：写 `nfcretry` 标记 + 重启直达上膛页（复用现有机制）
- 绑定存 SPIFFS `/quick.txt`；BACKUP 会一并备份/恢复
- 选择器模态循环会喂 RF 侧的 6s 任务看门狗（之前不喂会 panic 重启）
